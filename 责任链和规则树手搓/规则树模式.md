# 规则树模式

## 核心架构

```
                    ┌─────────────────────────────────────────┐
                    │           AbstractRouterClass           │
                    │           (整合类: Handler+Mapper)        │
                    └─────────────────────────────────────────┘
                      ▲              ▲              ▲
                      │              │              │
             ┌────────┘       ┌──────┘              └────────┐
             │                │                               │
  ┌──────────┴─────┐  ┌──────┴──────┐               ┌────────┴──────┐
  │  TreeHandler   │  │ TreeMapper  │               │  TreeSupport  │
  │  (执行接口)     │  │ (路由接口)   │               │  (空实现多线程) │
  └────────────────┘  └─────────────┘               └───────────────┘
                                                             ▲
                                                             │
                                                    ┌────────┴────────┐
                                                    │  业务 Node 类    │
                                                    │ 按需重写 get/   │
                                                    │ doApply         │
                                                    └─────────────────┘
```

## 两个接口

### 1. TreeHandler — 执行逻辑

```java
public interface TreeHandler<T,D,R> {
    R apply(T request, D dynamic) throws Exception;
}
```

- 定义**"做什么"**
- `apply()` 是执行业务逻辑的入口
- `T` = 请求类型，`D` = 动态上下文，`R` = 返回结果

### 2. TreeMapper — 路由映射

```java
public interface TreeMapper<T,D,R> {
    TreeHandler<T, D, R> get(T request, D dynamic) throws Exception;
}
```

- 定义**"下一步找谁"**
- `get()` 根据请求和上下文，决定返回哪个处理器
- 返回 null 表示链走到尽头

## 一个整合类 — AbstractRouterClass

同时实现 `TreeHandler` 和 `TreeMapper`，提供两个核心方法：

### router() — 路由引擎

```java
public R router(T request, D dynamic) throws Exception {
    TreeHandler<T, D, R> handler = get(request, dynamic);  // ① 找下一个节点
    if (handler != null) return handler.apply(request, dynamic); // ② 有就执行
    return defaultHandler.apply(request, dynamic);  // ③ 没有就走默认
}
```

三步：**查找 → 执行 → 兜底**

利用 Java **动态分派**：`router()` 里调用的 `get()` 实际执行的是子类重写后的版本。

### apply() — 执行骨架

```java
public R apply(T request, D dynamic) throws Exception {
    mulitWork(request, dynamic);   // ① 多线程预加载（模板方法）
    return doApply(request, dynamic);  // ② 执行业务
}
```

- `mulitWork()` 留给需要多线程预加载的子类实现
- `doApply()` 是真正业务逻辑，子类必须实现

---

## 一个支持类 — TreeSupport

```java
public abstract class TreeSupport extends AbstractRouterClass {
    @Override
    public void mulitWork(Object request, Object dynamic) {
        // 空实现
    }
}
```

- 空实现 `mulitWork`，让不需要多线程的节点免于重复写空方法
- 使用 raw type（Object），简化泛型

## Node 类 — 按需重写

每个节点只管两件事：

| 方法 | 职责 | 示例 |
|------|------|------|
| `get()` | 决定下一个节点路由到谁 | `return secondNode;` |
| `doApply()` | 当前节点的业务逻辑 | `return "处理完成: " + request;` |

**责任链：**

```
rootNode → firstNode → secondNode → thirdNode(终节点)
```

每个节点的 `doApply()` 处理完自己的逻辑后调 `router()` 把请求传给下一个，终节点直接返回结果，逐层回传。

## 工厂类 — TreeFactory

```java
@Service
public class TreeFactory {
    private final rootNode rootNode;

    public TreeFactory(rootNode rootNode) {
        this.rootNode = rootNode;
    }

    public TreeHandler<String, DynamicContext, String> handler() {
        return rootNode;  // 返回根节点作为入口
    }

    @Data @Builder @AllArgsConstructor @NoArgsConstructor
    public static class DynamicContext {
        private int level;
        @Builder.Default
        private Map<String, Object> dataObjects = new HashMap<>();

        public <T> void setValue(String key, T value) { ... }
        public <T> T getValue(String key) { ... }
    }
}
```

- 用 Spring `@Service` 管理，构造器注入根节点
- `handler()` 返回根节点，外部调用入口
- `DynamicContext` 作为请求上下文，携带数据在链中传递

## 完整调用链路

```java
// 外部调用
String result = treeFactory.handler().apply("订单", ctx);

// 内部执行流程：
rootNode.apply("订单", ctx)
  ├─ rootNode.mulitWork()         (TreeSupport 空实现)
  ├─ rootNode.doApply()
  │    └─ rootNode.router()
  │         ├─ get() → firstNode  (动态分派)
  │         └─ firstNode.apply()
  │              ├─ mulitWork()   (空)
  │              ├─ doApply()
  │              │    └─ router()
  │              │         ├─ get() → secondNode
  │              │         └─ secondNode.apply()
  │              │              ├─ mulitWork() (空)
  │              │              ├─ doApply()
  │              │              │    └─ router()
  │              │              │         ├─ get() → thirdNode
  │              │              │         └─ thirdNode.apply()
  │              │              │              ├─ mulitWork() (空)
  │              │              │              └─ doApply()
  │              │              │                   └─ return "处理完成: 订单"
  │              │              └─ ← 结果逐层返回
  │              └─ ← 结果逐层返回
  └─ ← 最终结果 "处理完成: 订单"
```

## 总结

| 层次 | 类 | 职责 |
|------|-----|------|
| 接口 | `TreeHandler` | 定义执行契约 |
| 接口 | `TreeMapper` | 定义路由契约 |
| 整合 | `AbstractRouterClass` | 提供 `router()` 和 `apply()` 模板 |
| 支持 | `TreeSupport` | 空实现多线程方法 |
| 业务 | `rootNode`, `firstNode`... | 按需重写 `get()` 和 `doApply()` |
| 工厂 | `TreeFactory` | 创建上下文，暴露根节点入口 |
